# 면접 설명 가이드

## 주요 주장별 질문과 준비물

| 주요 주장 | 사전 인터뷰 꼬리질문 | 직무 인터뷰 심화 질문 | 아키텍처로 설명할 요소 | 추가 확인 정보 |
|---|---|---|---|---|
| 개인 프로젝트 | 짧은 기간에 무엇을 포기했나요? | 우선순위를 바꾼 시점과 근거는 무엇인가요? | 지원 범위와 비목표 | 커밋별 의사결정 타임라인 |
| OpenDART snapshot | 원본을 왜 그대로 DB에 넣지 않았나요? | revision과 manifest가 재현성을 어떻게 보장하나요? | 수집, hash, manifest, 적재 | 공개 가능한 snapshot 예시 |
| 0 값 오류 수정 | 처음에는 왜 발견하지 못했나요? | 최신 revision과 지표별 우선순위가 충돌하면 어떻게 하나요? | account, statement, revision 선택 순서 | 당시 검토한 다른 대안 [확인 필요] |
| SQL과 RAG 분리 | 모두 RAG로 처리하면 안 되나요? | 어떤 질문이 결정론 경로와 검색 경로로 나뉘나요? | Supervisor, SQL, pgvector, Evidence Gate | 라우팅 오분류 사례 |
| 근거 상태 | INSUFFICIENT와 SYSTEM_UNAVAILABLE의 차이는 무엇인가요? | 상태 전이가 잘못되면 어떤 사용자 위험이 생기나요? | 공개 상태 계약과 fail-closed 흐름 | 실제 운영 장애 사례 없음 |
| AI 도구 활용 | AI가 만든 코드를 어떻게 검증했나요? | 제안을 거절하거나 수정한 사례가 있나요? | 사람의 수용 기준과 테스트 경계 | 구체적 거절 로그 [확인 필요] |
| 배포 경험 | 지금도 서비스가 열려 있나요? | 시점 확인과 지속 운영을 어떻게 구분하나요? | 앱, DB, 외부 API의 배포 경계 | 2026-08-06 응답 확인, 상시 가용성과 지속 운영은 미검증 |

## 대표 프로젝트 5분 설명 순서

1. 재무 질문의 숨은 조건과 문제 범위를 설명합니다.
2. 개인 프로젝트에서 직접 책임진 범위를 말해요.
3. SQL 사실 경로와 RAG 문맥 경로를 그림으로 구분합니다.
4. 0 값 오류를 관찰, 원인, 선택, 회귀 테스트 순으로 설명합니다.
5. 근거가 부족할 때 답변을 만들지 않는 정책을 보여 줍니다.
6. 사용자 비교와 성능 우위는 아직 입증하지 않았다고 닫습니다.

## 답변에서 피할 표현

- 완전한 멀티 Agent 시스템
- 금융 판단을 자동화한 서비스
- 대규모 데이터 처리 성능을 입증
- 운영 중인 공개 서비스
- AI가 알아서 구현
- 테스트 개수가 많아서 품질이 높음

코드와 테스트로 끝까지 설명할 수 있는 범위만 사용합니다.
